Know Your Agent.

Banks run Know Your Customer before they open an account. This is the same check for AI agents. Every agent on this register has an ID, an owner who signed for it, and a record of what it has done. Paste an agent's ID, or type the name of an owner or an agent, to see who stands behind it and whether its record is clean.

An ID gives one of three answers: identified with a verified owner, identified with an owner on record, or unknown. A name finds owners who chose to show it. See every listed owner.

1. Put an agent on the register

npx @sheaf-labs/kya init --owner "Your name or company"
npx @sheaf-labs/kya join your-agent

Two commands, no account. The keys are made on your machine and stay there. The register sees only public keys and signatures. Your agent then has an ID anyone can check, with you as the owner on record. Prove you control your domain with kya verify your-domain and you are a verified owner. Any system that runs or checks AI agents can also issue IDs and write receipts in the published format. The first one is Sheaf: every Sheaf account is on the register from the day it is made. An owner can hide its names or leave at any time. How to join.

2. What a check answers

Identified, owner verified
An owner signed for this agent and has proved who it is: it controls the domain it named (a token placed in the domain's DNS or on its website), or the register's keeper has reviewed it. A Companies House entry may be attached to a proved domain.
Identified, owner on record
An owner signed for this agent. It has not yet proved who it is.
Unknown
No agent with this ID is on the register. Treat it as anonymous.

Every answer comes with the agent's Record of Action: what it has done, how often a person stopped it, and a score anyone can recompute from the receipts. What an agent may do with each answer is your decision. A bank might let an unknown agent read a price list and nothing more.

3. How the register works

  1. An ID is a key. An agent's ID is its public key. Any program can make a key; what it cannot make is an owner's signature over it. The owner is a company or a person. They hold a root key and sign each agent's ID with it. An ID with no owner's signature counts as unknown.
  2. Every action adds a receipt. Each time the agent acts through a verifier, the verifier adds a signed receipt to the agent's record: what kind of action, what the verdict was, and when. Each receipt names the one before it. The content of the action stays with the owner. The register holds only hashes.
  3. Anyone can check. Before your systems deal with an agent, look it up. One agent can also challenge another directly: A sends B a challenge, B signs it, A asks the register. Under two seconds, and both records gain a receipt. See the handshake. The answer, the owner's signature and the whole receipt chain can be checked from the public keys alone. You do not have to trust this site.

4. Open, and nobody's

The format, the signed test vectors, the kya tool, a Python client and this register's server are published under Apache-2.0 at github.com/jackmitchelwidman/know-your-agent. Anyone may run a register from it with docker compose up. Registers that speak the format answer each other's lookups, so an agent entered on one can be checked from another. Each register re-checks the signatures itself and trusts no peer's word.

This register is the first one. It was started by Sheaf Labs, which wrote the format and runs it today. The plan is a body of the register's members, in which every operator and every system that issues IDs has a seat. How that works. To check your own implementation, clone the repository and run node know-your-agent/spec/vectors/verify.mjs: fixed keys and signed objects for every part of the format. Read the format.
